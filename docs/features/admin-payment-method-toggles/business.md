# Глобальная доступность способов оплаты — продуктовые требования

- **Статус:** approved
- **Scope revision:** 2
- **Основание статуса:** пользователь явно утвердил BR-001–BR-006,
  AC-001–AC-008 и non-goals Scope Contract revision 2.

## Проблема

Видимость поддержанных способов оплаты зафиксирована в коде бота. Если один из
провайдеров временно недоступен, администратор не может оперативно скрыть его на
всех новых экранах оплаты, не дожидаясь перезапуска Django или бота.

## Ожидаемая ценность

- Администратор единообразно управляет доступностью способов оплаты сразу для
  всех текущих продуктов.
- Пользователь видит только доступные способы и не получает новую платёжную
  кнопку временно отключённого провайдера.
- Текущее платёжное поведение сохраняется сразу после релиза и при выборе
  активного способа.

## Акторы

- **Администратор Django:** включает или выключает Telegram Stars и Crypto Pay.
- **Пользователь Telegram-бота:** открывает экран оплаты MTProxy, VPN или
  подарочного сертификата и выбирает доступный способ.

## Scope

- единая глобальная активность Telegram Stars и Crypto Pay;
- управление активностью через Django admin;
- применение состояния при новом открытии экранов оплаты MTProxy, VPN и
  подарочного сертификата;
- явное состояние экрана, когда все способы выключены;
- сохранение текущей видимости сразу после миграции.

## Пользовательские сценарии

### S-001. Оба способа активны

1. Администратор оставляет Telegram Stars и Crypto Pay активными.
2. Пользователь открывает любой из трёх экранов оплаты.
3. Бот показывает Telegram Stars первым, Crypto Pay вторым.

### S-002. Один способ выключен глобально

1. Администратор выключает Telegram Stars или Crypto Pay.
2. Пользователь открывает экран оплаты MTProxy, VPN или подарочного
   сертификата.
3. На каждом экране бот показывает только оставшийся активный способ.

### S-003. Все способы выключены

1. Администратор выключает Telegram Stars и Crypto Pay.
2. Пользователь открывает любой из трёх экранов оплаты.
3. Бот не показывает платёжные кнопки и выводит текст
   `Оплата временно недоступна`.

### S-004. Изменение применяется без рестарта

1. Администратор меняет активность способа при работающих Django и боте.
2. Пользователь заново открывает соответствующий экран оплаты.
3. Бот отражает новое состояние без перезапуска процессов.

### S-005. Управление только поддержанными способами

1. Администратор открывает управление способами оплаты.
2. В admin доступны Telegram Stars и Crypto Pay с независимыми глобальными
   переключателями.
3. Администратор не может добавить произвольный способ оплаты.

## Бизнес-требования

- **BR-001.** Для каждого поддержанного способа оплаты администратор управляет
  одной глобальной активностью. Одно значение одновременно определяет
  видимость способа на экранах оплаты MTProxy, VPN и подарочного сертификата;
  per-product настройки отсутствуют.
- **BR-002.** Django admin предоставляет управление только способами,
  поддержанными кодом. Администратор не может создать произвольный способ
  оплаты; Telegram Stars и Crypto Pay должны оставаться доступными для
  переключения.
- **BR-003.** Изменение активности должно отражаться при следующем открытии
  любого из трёх экранов оплаты без перезапуска Django или Telegram-бота.
- **BR-004.** Если нет ни одного активного способа, каждый экран оплаты
  показывает текст `Оплата временно недоступна` вместо кнопок способов оплаты.
- **BR-005.** Добавление в будущем нового поддержанного кодом провайдера должно
  позволять управлять им одним глобальным переключателем для всех продуктов,
  без per-product конфигурации и без универсального plugin framework.
- **BR-006.** Data migration создаёт Telegram Stars и Crypto Pay активными,
  поэтому сразу после релиза видимость и порядок текущих способов оплаты не
  меняются.

## Критерии приёмки

- **AC-001 (BR-001, BR-002).** В Django admin администратору доступны Telegram
  Stars и Crypto Pay с независимыми глобальными переключателями; добавить
  произвольный третий способ через admin невозможно.
- **AC-002 (BR-001, BR-004).** На каждом из экранов MTProxy, VPN и подарочного
  сертификата соблюдается одна матрица видимости:
  - оба активны — показаны Stars первым и Crypto Pay вторым;
  - активен только Stars — показан только Stars;
  - активен только Crypto Pay — показан только Crypto Pay;
  - оба выключены — нет платёжных кнопок и показан текст
    `Оплата временно недоступна`.
- **AC-003 (BR-001).** Одно выключение любого способа в admin скрывает его
  сразу на всех трёх продуктовых экранах; отдельных значений для продуктов нет.
- **AC-004 (BR-003).** В уже работающих Django и bot процессах администратор
  меняет переключатель, после чего следующее открытие соответствующего экрана
  отражает новое состояние без рестарта. Для MTProxy это распространяется и на
  повторное открытие экрана через существующую кнопку продления.
- **AC-005 (BR-006).** После применения data migration обе поддержанные записи
  существуют и активны; без действий администратора все три экрана сохраняют
  текущие две кнопки в порядке Stars → Crypto Pay.
- **AC-006 (ограничение существующих flows).** Выбор отображаемой Stars- или
  Crypto Pay-кнопки запускает действующий сценарий соответствующего продукта
  без изменения цены, invoice, fulfilment или результата покупки.
- **AC-007 (BR-005).** Для нового способа, который в будущем будет поддержан
  кодом, предусмотрено одно глобальное состояние для всех продуктовых экранов;
  его подключение не требует отдельных настроек MTProxy, VPN и подарочного
  сертификата или универсального механизма произвольных провайдеров.
- **AC-008 (non-goal).** Старое сообщение с ранее показанной кнопкой не входит
  в проверку динамической видимости: требования применяются при новом открытии
  экрана.

## Supersedes note

Этот документ заменяет только безусловную видимость обоих способов из BR-001 и
AC-001 утверждённой фичи `cryptopay-all-products`: теперь способ показывается на
новом экране оплаты только когда он активен. Порядок Stars → Crypto Pay при двух
активных способах и все существующие платёжные сценарии сохраняются.
Исторический документ `cryptopay-all-products` не переписывается.

## Non-goals

В изменение не входят:

- отдельная доступность способов для разных продуктов;
- редактирование названий или порядка способов через admin;
- создание произвольных провайдеров через admin или универсальный plugin
  framework;
- реализация новых провайдеров, включая СБП или эквайринг;
- управление credentials или runtime-конфигурацией провайдеров через admin;
- дополнительная проверка нажатия кнопки в уже показанном старом сообщении;
- изменение цен, invoice, fulfilment или результатов действующих Stars и
  Crypto Pay flows;
- изменения в `apps/music` или `apps/notifications`;
- merge или production deploy.

## Ограничения и границы

- Scope зафиксирован как неизменяемый `scope_revision: 2`.
- База данных является source of truth для активности способов оплаты.
- Telegram Stars остаётся первым, Crypto Pay вторым, когда активны оба способа.
- Решение ограничено глобальными переключателями уже поддержанных способов и
  следует YAGNI.
- Новое обязательное пользовательское поведение требует отдельного
  `scope_change_request`.

## Риски

- Несогласованное применение одного переключателя на трёх экранах может
  оставить выключенный способ видимым для части продуктов и нарушить BR-001.
- Задержанное применение изменения может потребовать рестарта и нарушить
  BR-003.
- Пустой экран без явного текста при двух выключенных способах нарушит BR-004.
- Неверное начальное состояние после миграции может неожиданно изменить
  доступные способы сразу после релиза и нарушить BR-006.

Риски описывают возможные нарушения утверждённых требований и не добавляют
нового обязательного поведения.
